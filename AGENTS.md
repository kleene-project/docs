# kleene-docs

Source of https://kleene.dev, the documentation site for Kleene (a FreeBSD jail/container manager: `klee` is the CLI client, `kleened` the backend). Built with MkDocs + Material theme, deployed to GitHub Pages from `main`. Content is Markdown under `docs/`; the `klee` command reference and the glossary are generated at build time from YAML in `data/`. Much prose was forked from Docker's docs (see NOTICE/LICENSE, Apache-2.0).

## Dev environment & build

- `make setup`  creates `.venv` and installs `requirements.txt` (pinned versions; re-runs when requirements.txt changes).
- `make serve`  runs `.venv/bin/mkdocs serve` at http://127.0.0.1:8000/.
- `make clean`  removes `.venv` and `site/`.
- Full check (same as CI): `.venv/bin/mkdocs build --strict`
- There is no test suite or linter. The strict build is the check: CI (`.github/workflows/deploy.yml`) runs it on every PR and push to `main`, and deploys only from `main`. Python 3.12 in CI; the system python3 is 3.13, and there is no system pip (use the venv).

## Layout

- `docs/` pages. Nav is `docs/SUMMARY.md` (mkdocs-literate-nav), not the `nav:` key in `mkdocs.yml`.
- `docs/reference/klee/*.md` (except `cli.md`, `configure-klee.md`) are NOT checked in. They are generated by `scripts/gen_cli_reference.py` from `data/klee-reference/klee_<name>.yaml`.
- `docs/glossary.md` is generated by `scripts/gen_glossary.py` from `data/glossary.yaml`. Edit the YAML, not a page. Terms become `##` headings; cross-references use `#anchor` links.
- `data/klee-reference/*.yaml` are produced by the klee repo (`make docs` there). Do not hand-edit them; regenerate them from klee (commit "Regenerate the klee command reference").
- `docs/reference/kleened/kleened-v0.0.1.yaml` is the OpenAPI spec, rendered client-side by `docs/assets/redoc/redoc.standalone.js` via `<redoc>` in `kleened-v0.0.1.md`. Vendored JS, leave it alone.
- `overrides/main.html` hides the "edit" button on generated klee pages. `docs/assets/css/kleene.css` holds brand colors.
- `mkdocs.yml` `redirects` plugin maps old URLs; add an entry when moving or renaming a page.

## Conventions (from docs/contribute/)

- New page: short one- or two-word, dash-separated file name (`nullfs-mounts.md`). Front matter requires `title` and `description` (optional `hide: [toc, navigation]`).
- Every new page MUST be added to `docs/SUMMARY.md`, in the section matching its directory. Unlisted pages fail the strict build.
- Wrap prose at about 80 characters, so review comments can target small chunks.
- Voice and naming: see `docs/contribute/style-guide.md` (sentence-case headings; drivers in code style `ipnet`/`vnet`; tutorial in second person).
- Admonitions use `!!! note` style (the `admonition` extension). Icons use Material emoji shortcodes (`pymdownx.emoji`), not the old Jekyll/glyphicon syntax.
- Commit messages: short imperative sentence, no prefix (e.g. "Fix brand colors, icon shortcodes and the missing logo after cutover"). Work lands via PR branches such as `docs/<topic>`.

## Pitfalls

- `strict: true`: any warning (broken internal link, page missing from SUMMARY.md, missing image) fails the build.
- A YAML file in `data/klee-reference/` without a matching `reference/klee/<name>.md` entry in SUMMARY.md makes `gen_cli_reference.py` exit with an error, and the reverse (a nav entry with no YAML) gives a missing page. Add a nav entry for every new klee subcommand, or delete the stale YAML. The shortcut names (`klee isc`, `klee rmc`, ...) are also separate YAML files.
- Generated pages link with absolute paths such as `/reference/klee/<name>/`, and the Kleened API page loads `/assets/redoc/...` from the site root, so `mkdocs serve` must be used at the root, not under a sub-path.
- Leftovers from the old Jekyll site (not used by MkDocs, do not extend): `_site/`, `.jekyll-cache/`, `.bundle/`, and `data/toc.yaml`. `site/` and `.venv/` are gitignored build output.
- Untracked `kleene.dev_screendump*.png` in the repo root are stray screenshots, not site assets. Do not commit them.
